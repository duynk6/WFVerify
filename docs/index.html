Cách ly STDOUT / STDERR Tuyệt đối

Kênh stdout được bảo lưu duy nhất cho các thông điệp JSON-RPC của giao thức MCP. Toàn bộ nhật ký runtime, thông báo lỗi và tracing được điều hướng 100% sang stderr (LogToStandardErrorThreshold = LogLevel.Trace), đảm bảo không làm vỡ stream dữ liệu của AI Client.

Luồng STA Chuyên trách & Chống Deadlock

FlaUI và UIA3 giao tiếp qua Windows COM không an toàn luồng. Mọi thao tác UI được đẩy vào hàng đợi của luồng STA duy nhất (UiThread.RunAsync) kèm cơ chế Poison Detection (cảnh báo session hỏng sau 2 lần timeout liên tiếp) và phát hiện Modal Dialog tự động.

1

AI Client Request

AI Agent gửi yêu cầu tools/call (VD: wf_invoke, wf_screenshot, wf_get_ui_tree) qua kênh Stdio JSON-RPC.

Lên lịch thực thi trên luồng STA. Tự động kiểm tra Modal Dialog. Nếu thất bại ở Pattern chuẩn (Invoke) sẽ tự động fallback sang Hardware Click / LegacyIAccessible.

4

Đóng gói kết quả dưới dạng { "ok": true, "data": ..., "warnings": [...] } hoặc { "ok": false, "error": ... } trả về cho AI Agent.

Cài đặt & Tích hợp vào AI Clients

Cài đặt nhanh (khuyên dùng)

Chạy install.ps1 ở gốc repo — script tự dotnet publish, tự suy ra đường dẫn .exe từ vị trí thực tế (không hardcode đường dẫn) rồi đăng ký thẳng với client. Với client cần sửa file JSON, script tự merge và backup file cũ trước khi ghi đè.

PowerShell 
.\install.ps1 -Client claude-code   # nhanh nhất, không đụng file JSON
.\install.ps1 -Client claude-desktop
.\install.ps1 -Client cursor
.\install.ps1 -Client antigravity
.\install.ps1                       # in JSON để dán tay cho client khác

Mặc định whitelist đúng thư mục repo cho WFVERIFY_ALLOWED_ROOTS; thêm -AllowedRoots "..." nếu cần. Đã publish rồi thì thêm -SkipPublish.

Yêu cầu Môi trường
  • Hệ điều hành: Windows 10/11 x64 hoặc Windows Server có hỗ trợ Desktop Experience.
  • Runtime: .NET 8.0 Runtime (Windows Desktop x64).
  • Môi trường hiển thị: Interactive Desktop Session (màn hình mở, không bị lock screen hoặc Remote Desktop disconnected).

UI Automation không phải API chạy ở đâu cũng được:

Ràng buộcChi tiết
Interactive desktop sessionCần phiên desktop đang mở khoá. Không chạy được qua SSH, Windows Service, hay CI agent chạy nền — muốn dùng trong CI phải có RDP session giữ mở hoặc self-hosted runner ở chế độ interactive.
Màn hình khoáKhi Windows khoá màn hình, click sẽ thất bại và wf_screenshot trả ảnh đen.
QuyềnỨng dụng đích chạy elevated (Run as administrator) thì server cũng phải elevated, nếu không UIA bị UIPI chặn và mọi thao tác đều thất bại.

Ảnh chụp màn hình có thể lộ dữ liệu nhạy cảm

wf_screenshot chụp nguyên cửa sổ ứng dụng — bao gồm dữ liệu khách hàng, số liệu tài chính, thông tin đăng nhập đang hiển thị — rồi gửi thẳng cho model. Đặt WFVERIFY_DISABLE_SCREENSHOT=1 để vô hiệu hoá hẳn tool này.

Chế độ chỉ-đọc cho production

Đặt WFVERIFY_READONLY=1 để chặn wf_set_value/wf_grid_set_cell (lỗi READONLY_MODE) và chặn wf_invoke vào control có nhãn khớp từ khoá ghi dữ liệu (Ghi, Lưu, Xóa, Cập nhật, Duyệt, Save, Delete, Update, Insert, Submit, Apply). Tuỳ biến bằng WFVERIFY_READONLY_BLOCKLIST (`;`-separated); so khớp theo ranh giới từ nên Nghiên cứu không bị chặn bởi Ghi.

Không đưa mật khẩu vào lời gọi tool

wf_launch_app nhận argumentsFile (mảng JSON hoặc file text mỗi dòng một tham số) và placeholder ${env:TEN_BIEN}, ${file:C:\path\creds.json#sql.password} trong arguments/environment — server tự giải trước khi đưa vào ProcessStartInfo.ArgumentList, không bao giờ lộ ra command line.

PathGuard whitelist

WFVERIFY_ALLOWED_ROOTS là hàng rào duy nhất cho wf_launch_app, wf_analyze_form, wf_analyze_project. Đặt càng hẹp càng tốt; bỏ trống thì mặc định là thư mục làm việc của server. Đường dẫn ngoài whitelist bị chặn với PATH_DENIED.

Không giết ứng dụng nó không khởi chạy

Với app phải đăng nhập / chọn SQL thủ công, dùng wf_attach_app rồi kết thúc bằng wf_detach_app (chỉ drop session, không đụng tiến trình). wf_close_app sẽ từ chối nếu tiến trình không do server khởi chạy.

Cú pháp Selector Phân cấp

Bộ định vị hỗ trợ tìm kiếm đa cấp bằng toán tử > . Nếu tìm kiếm thất bại, server sẽ tự động gợi ý danh sách các control gần đúng nhất qua thuật toán khoảng cách Levenshtein.

Tiền tố Cú pháp mẫu Ý nghĩa
id: id:txtUsername hoặc #txtUsername Khớp chính xác thuộc tính AutomationId (tên biến control WinForms).
name: name:Đăng nhập Khớp chính xác thuộc tính Name / Text hiển thị.
name~: name~:Đơn hàng Tìm kiếm control có chứa chuỗi con (không phân biệt hoa thường).
type: type:Button, type:Edit Khớp theo ControlType trong chuẩn UIA3.
grid: id:dgOrders > grid:2,1 Định vị ô tại dòng 2, cột 1 trong bảng dữ liệu DataGridView.
idx: type:Button > idx:0 Lấy phần tử thứ n trong danh sách kết quả khớp.
> id:tabMain > id:tabOrders > id:dgOrders Toán tử phân cấp cha - con để thu hẹp phạm vi tìm kiếm.
Selector cho cửa sổ (windowSelector)

Dùng tập tiền tố nhỏ hơn: id:, name:, name~:, class:, title:, title~:. Khớp cửa sổ cấp cao nhất trước, sau đó tới form con MDI (duyệt MDIClient qua Win32). Một windowSelector không bao giờ khớp vào tab hay panel — khi nhiều tab của cùng form dùng chung id control (VD fg, txtMaHang), phải scope bằng selector phân cấp id:tabTheoDoi > id:fg. Một id:fg trống ngữ cảnh sẽ trả về control đang hiển thị (tab đang active).

Bộ 15 Rule Phân tích tĩnh Roslyn (WF001 – WF060)

Mã Rule Mức độ Tên vi phạm Mô tả & Hướng khắc phục
WF001 Error Broken Event Handler Event được gán trong Designer.cs nhưng method xử lý không tồn tại trong code-behind.
WF002 Warning Orphaned Event Handler Method dạng event handler (có đuôi _Click, _Load) nhưng không được gán vào sự kiện nào.
WF010 Warning Control Overlap Hai control trong cùng một container bị đè tọa độ lên nhau gây che khuất giao diện.
WF011 Warning Control Clipped By Container Control có tọa độ/kích thước vượt ra ngoài vùng hiển thị (ClientSize) của container cha.
WF012 Info Negative Location Control có tọa độ X hoặc Y âm trong container.
WF020 Warning Duplicate TabIndex Trùng TabIndex giữa các control có thể tương tác (Button, TextBox) cùng cấp.
WF021 Info Missing TabIndex Control tương tác không được thiết lập TabIndex hoặc thứ tự TabIndex bị ngắt quãng.
WF022 Info Illogical TabIndex Order Thứ tự phím Tab không khớp với thứ tự đọc tự nhiên từ trên xuống dưới, từ trái qua phải.
WF030 Error Dock and Anchor Conflict Sử dụng đồng thời Dock = Fill với thuộc tính Anchor khác mặc định.
WF031 Warning Default Anchor in Resizable Form hoặc container có thể co giãn nhưng control con vẫn giữ Anchor mặc định Top, Left.
WF040 Warning Missing AccessibleName Control tương tác thiếu AccessibleName và Text hiển thị rỗng hoặc là tên mặc định.
WF041 Info Default Control Name Control vẫn giữ tên mặc định do Designer tự sinh (VD: button1, textBox2).
WF050 Warning Hardcoded Font Font được hardcode trên control con khác với Font kế thừa từ Form cha gây lỗi hiển thị khi đổi theme.
WF051 Info Missing AutoScaleMode Form chưa cấu hình AutoScaleMode = Dpi hoặc Font dẫn đến vỡ layout trên màn hình HiDPI.
WF060 Info Dead Control Control được khai báo và khởi tạo trong Designer nhưng quên không thêm vào Controls.Add().

Bảng Mã Lỗi Chuẩn & Xử lý Sự cố

BLOCKED_BY_MODAL

Nguyên nhân: Thao tác UI bị chặn do ứng dụng đang bật một hộp thoại thông báo (MessageBox hoặc Form con dạng Modal).
Khắc phục: Gọi tool wf_dialog_respond với nút bấm phù hợp ("OK", "Cancel") trước khi thực hiện thao tác tiếp theo.

ELEMENT_NOT_FOUND

Nguyên nhân: Không tìm thấy control theo selector đã cho.
Khắc phục: Kiểm tra danh sách candidates gợi ý gần đúng trong error payload hoặc gọi wf_get_ui_tree để lấy danh sách tên control thực tế.

WINDOW_NOT_FOUND

Nguyên nhân: windowSelector không khớp cửa sổ nào — thường gặp khi nhắm vào form con MDI bằng selector cấp cao nhất.
Khắc phục: Lỗi trả về liệt kê sẵn các form MDI đang mở kèm gợi ý selector phân cấp; hoặc gọi wf_list_windows để xem toàn bộ cửa sổ (kể cả MDI child).

PATH_DENIED

Nguyên nhân: Đường dẫn file nằm ngoài danh sách whitelist của PathGuard.
Khắc phục: Thêm thư mục vào biến môi trường WFVERIFY_ALLOWED_ROOTS (phân tách bằng dấu chấm phẩy ;).

TIMEOUT & POISON SESSION

Nguyên nhân: Thao tác UI vượt quá thời gian chờ (mặc định 10s). Nếu xảy ra 2 lần liên tiếp, hệ thống sẽ kích hoạt cờ Poisoned Session.
Khắc phục: Đóng app bằng wf_close_app(force=true) và khởi động lại phiên làm việc mới.

READONLY_MODE

Nguyên nhân: Server đang chạy với WFVERIFY_READONLY=1 nên wf_set_value/wf_grid_set_cell bị chặn, và wf_invoke bị chặn khi nhãn control khớp từ khoá ghi dữ liệu.
Khắc phục: Đây là hành vi cố ý cho môi trường production. Tắt biến môi trường nếu thực sự cần ghi, hoặc tuỳ biến danh sách chặn bằng WFVERIFY_READONLY_BLOCKLIST.

AMBIGUOUS

Nguyên nhân: wf_select khớp item bằng Contains nhưng trúng nhiều hơn 1 mục (VD "May 1" trúng cả "May 1" và "May 10").
Khắc phục: Dùng tên khớp chính xác tuyệt đối, hoặc dùng index theo danh sách [index] tên mà lỗi trả về.
